Simulamos una arquitectura con dos aplicaciones independientes: el Servidor de Identidad en el puerto 8000 y el Portal Médico en el puerto 8001

Ficheros que debes tener:

CAI3-Parte1/
├── requirements.txt
├── auth_server.py
├── auth_client.py
├── generar_claves.py
├── redteam/
│   ├── forjar_jwt.py
│   ├── probar_hardening.py
│   └── probar_tokens.py
└── templates/
    ├── enroll_login.html
    ├── setup_mfa.html
    ├── login.html
    └── portal.html

Paso 1: Crear el entorno virtual e instalar dependencias

a) En Windows (PowerShell o CMD)
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

b) En Linux (Bash)
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

Paso 1.b: Generar claves y secretos (solo la primera vez)

python generar_claves.py

Crea keys/jwt_private.pem (clave privada RSA con la que se firman los JWT) y el fichero .env
con secretos aleatorios. Sin este paso los servidores no arrancan. Ni keys/ ni .env se suben
a git ni se incluyen en el zip: cada instalación genera los suyos.

Paso 2: Arrancar los dos servidores (Necesitas 2 terminales)

a. Terminal 1 — Arrancar el Servidor de Autenticación (auth_server.py):
Con el entorno virtual (venv) activado: python auth_server.py
b. Terminal 2 — Arrancar el Portal Médico (auth_client.py): python auth_client.py

Paso 3: Acceder al laboratorio

1. Abre tu navegador y entra en la dirección: http://localhost:8001
2. Haz clic en "Configurar FreeOTP". Se abre el servidor de identidad y te pide usuario y contraseña
   (rocio / SuperSegura2026! o dr_gasca / MedicoSegura2026!).
3. Escanea el código QR con la aplicación FreeOTP de tu móvil (o introduce a mano la clave que aparece
   debajo) y confirma la vinculación escribiendo el código de 6 dígitos que genera la aplicación.
   Hasta que no se confirma el enrolamiento, ese usuario no puede iniciar sesión.
4. Vuelve al Portal Médico (http://localhost:8001), pulsa "Iniciar sesión con OAuth 2.0 + FreeOTP" e introduce
   usuario, contraseña y el código de 6 dígitos que genera tu móvil.

Notas:
- Los usuarios y sus semillas TOTP se guardan en memoria: al reiniciar auth_server.py hay que volver a
  enrolar el MFA (y borrar la cuenta antigua de FreeOTP, porque la semilla cambia). Cada usuario solo se
  puede enrolar una vez por arranque del servidor.
- Tras 5 intentos fallidos la cuenta queda bloqueada 5 minutos.

(Importante: No uses 127.0.0.1 en un sitio y localhost en otro, ya que las cookies de sesión OAuth 2.0 pueden fallar por diferencia de dominio).

(Importante: la cookie de sesión del portal lleva la marca Secure. Los navegadores la aceptan por HTTP en
localhost, pero no si abres el portal desde otra dirección, por ejemplo http://192.168.x.x:8001. En ese caso
pon COOKIE_SECURE=0 en el .env, o el inicio de sesión volverá siempre a la portada).

Paso 4 (opcional): Scripts de comprobación (con los dos servidores arrancados)

python redteam/probar_hardening.py   -> ataques contra la firma de los JWT
python redteam/forjar_jwt.py         -> intento de forjar un JWT con la clave antigua
python redteam/probar_tokens.py      -> claims, rotación de refresh tokens y logout

probar_tokens.py enrola a rocio y guarda su semilla en redteam/.semilla_rocio.json para poder repetirse.
Si rocio ya estaba enrolada desde el navegador y no hay semilla guardada, reinicia auth_server.py.
